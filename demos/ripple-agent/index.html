A language-model annotator for RIPPLE

Can a language model replace the person who corrects point tracks? In RIPPLE a person clicks a target once, watches the track, and clicks again wherever it has drifted. Here a language model makes those corrections: it views zoomed crops of a suspect frame, picks the target among candidate positions, and hands the frame to a person when it cannot tell. These are first results on one video, the Neural Activity dataset of the RIPPLE paper, with two Claude models: Opus and the much smaller Haiku.

  • 92.0average point precision of Claude Opus on ten tracks. Claude Haiku scores 92.1, the rule-based controller 88.5 and optical flow alone 42.3.
  • 15human clicks for ten tracks with Opus: ten to start the tracks and five on frames it deferred. Haiku needed 19. The original annotator made 158.
  • 129positions Opus placed itself, 0.71 px from the reference on average and never more than 2.2 px away.
  • 110 / 112identical queries on which Opus and Haiku gave the same answer.

How it works

the correction loop

  1. Start. One click on the target in the first frame. RIPPLE's own propagation code builds the track from optical flow.
  2. Flag. A frame is reviewed when forward and backward motion estimates disagree, when the patch under the track stops resembling the target, or when 60 frames have passed without a check.
  3. Propose. For the flagged frame the system lists up to six candidate positions: the tracker's current position, blob detections nearby, and the positions predicted from image motion.
  4. Decide. The language model sees a trusted reference crop, the frames in between, and the flagged frame with the candidates marked. It picks one candidate or abstains.
  5. Defer. An abstention, or a pick the model rates below 0.6 confidence, goes to a person and counts as one human click. Each new position becomes an anchor and RIPPLE rebuilds the track.

One decision: track 1, frame 71

Claude Opus chose B, confidence 0.85. “The terminal blob of the beaded process is centred on B; A sits just below-left of it off the blob, and C and D are the preceding puncta.”

A is the tracker's position before the correction. Each crop is 65 px wide, with contrast stretched to its centre so that a faint target stays visible beside a bright neighbour.

What these numbers are not

read before quoting

  • Agreement, not accuracy. The reference is the original annotator's finished RIPPLE track. We have not yet scored against the exhaustive manual segmentations of this video.
  • One video, ten tracks, one run per model. We have not repeated the runs, so we cannot say how much of the 3.5-point lead over the rule-based controller is run-to-run variation. The other four datasets of the RIPPLE paper are untested.
  • Settings tuned on the test tracks. We chose the flagging thresholds and the 60-frame review interval on these ten tracks. We did not tune the rule-based controller's weights, so it is a weak version of that baseline.
  • Agents, not API calls. Claude Opus and Claude Haiku each ran as one agent per track inside Claude Code. Each agent remembered its earlier decisions on its track, and we recorded no cost per decision.
  • Reference files were off limits by instruction only. The agents were told to read nothing but each query's own crops; nothing prevented them from opening the reference tracks.
  • A perfect simulated person. Deferred frames were answered with the exact reference position. A real person clicks a pixel or two off and takes time.
